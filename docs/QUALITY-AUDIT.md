# duet-ui quality audit

Audited 31 October 2026, starting from `1f7339e` / duet-ui 0.7.1. Scope: library source, existing tests/site consumers, supplied trip-site diagnoses and reference-library research. No physical Duo or native Safari UI was available. **Automated success is not real-device certification.** Final command results and PR URL are in [NOTES-QUALITY.md](../NOTES-QUALITY.md).

## Why defects escaped

The initial stack had 251 passing pure Node tests but almost no mounted-component interaction coverage. Playwright layout tests waited for removed `.duet-glass` markup; the same obsolete selector remained in production drag initiation. Unit geometry tests could not see either failure. Only four browser tests passed at setup. CI built/typechecked/unit-tested but never ran browser, accessibility, visual, SSR or installed-package checks. There was no enforced device evidence checklist. Signal emulation and physical Safari rendering had been treated too similarly.

The repair adds role-based mounted tests, real browser consumers, failing axe assertions, committed screenshots, a node-only server render and fresh tarball consumer build. The small `/quality` fixture is dev-only. Existing lab/pane/web-Duo coverage remains in the existing e2e directory. Baselines must be reviewed, never regenerated in CI.

## Findings by quirk class

| Class / finding | Verified root cause and evidence | Status / remaining risk |
| --- | --- | --- |
| Posture / fold / orientation | `stable()` must reconcile late outer sizes, inset arrival and visual viewport changes; detecting from viewport width alone is unsafe. Existing transit/unfold/transition fixtures exercise delayed readings. New browser sequence keeps the same input mounted through folded, unfolded and both tall/landscape turns. | Covered for injected signals; slow/fast hardware fold and first-paint timing pending. |
| Hinge / half-fold | Source has no physical hinge exclusion API; panes reflow by available width. A crease is not evidence of a CSS occlusion rectangle. New browser assertions keep edge controls off centre lines and preserve state across fold/turn. | Hardware angle, crease hit targets and laptop keyboard must be checked; no invented hinge gutter added. |
| Dynamic Island / safe areas | Geometry reserves measured Island/Live Activity growth and uses safe-area/viewport-fit signals. Worst measured growth is budgeted because Safari exposes no live Island rectangle. | Existing band/native-obstacle fixtures + strip screenshot pass subject to final report; unknown landscape Live Activity growth remains a device risk. |
| Safari tab / column | Column painting relies on document overflow outside the layout viewport, not ordinary fixed positioning. Unknown or framed contexts fall back inline; same-origin preview signals deliberately bypass physical detection. | Library layout contracts covered in two engines; overflow paint/hit routing is undocumented native behaviour requiring hardware. |
| URL bar / banner / tab restore | URL bar changes visual/page height independently; `stableHeight`, `offsetTop` and `visualBottom` prevent inappropriate mode changes and native overlap. | Expanded, collapsed and banner snapshots plus transitions; tab switch, BFCache and momentum on real Safari pending. |
| Keyboard | Editing + short visual viewport hide column controls without replacing layout. CSS also hides them while editable focus is active. A snapshot taken after filling an input is a keyboard/focus state, not a closed-menu baseline. | Explicit keyboard state and blur before ordinary screenshots; retained draft tested. Native dismissal, caret/scroll and fold-with-keyboard pending. |
| Split view | Safari does not reveal which pane owns the column; Duet draws both candidate columns and reserves page space. Hard-coding `left:0` can be wrong on the left column. | Split snapshot, native-obstacle geometry and pane tests; real divider resize/swap/left-right touch pending. |
| Menus: re-tapping current item | `select()` returned before `onSelect` when id equalled selected. Mounted test reproduced zero calls. This breaks scroll-spy section navigation. | **Fixed:** callback runs on every activation; saved scroll remains unchanged for reselect. Applications wanting changes only must guard explicitly. |
| Menus: off-screen document sidebar | Column CSS makes sidebar absolute at document y=0; without children nothing follows document scroll. Browser regression measured y=-898 after scrolling. | **Fixed:** absolute sidebar pins to visible document position on open/scroll/resize. Device compositor smoothness and rubber-band need checking. |
| Navigation: dragging controls | `useSideDrag` still hit-tested `.duet-glass`, absent from current rendered controls. Existing drag e2e failed after test selectors were repaired. | **Fixed:** initiate on `.duet-group`; regression checks side persistence and no accidental selection. |
| Focus: sidebar | No focus transfer or Escape handling. Role/user-event test failed while focus stayed on burger. | **Fixed:** first item, arrows/Home/End, Escape restores trigger; Tab dismisses without trapping page. This remains non-modal navigation. |
| Focus: pane and overflow menus | Menus had ARIA roles but no keyboard lifecycle. Role tests reproduced missing focus and return. | **Fixed:** shared focus lifecycle for pane menu and morph menu/dialog; real-browser keyboard test. VoiceOver and touch/external-keyboard interaction pending. |
| Accessibility: sidebar heading | Axe found small heading 3.28:1 (`#85858b` over `#f2f2f7`) in sidebar and overflow headings, below 4.5:1. | **Fixed:** strengthen the existing dim-heading token; failing axe regression retained. |
| Accessibility: destructive text | Axe found `#ff3b30` destructive pane text at 3.54:1 over white. Badge red had been reused for text. | **Fixed:** theme-aware `--duet-destructive` text token, separate from decorative badge fill; opaque `--duet-pane-menu-surface` prevents background-dependent contrast loss. Custom themes/glass backgrounds still require contrast review. |
| In-app preview after returning from another app | Existing 0.7.1 changelog records disappearing overflow controls with a solid sticky header (#235); device lifecycle/compositor interaction is not explained by static geometry. | **Known unresolved:** retain real app-switch/preview lifecycle check; no speculative fix claimed. |
| SSR / hydration | Server snapshot claims Safari Duo and rendered guard spans; iframe's first client render checks emulation state and omitted those spans, causing a browser hydration error. Runtime-only `emulatedSignals()` altered the initial tree. | **Fixed:** defer decorative guards until hydration. Node render without browser globals and browser pageerror checks cover fixture. Device first paint/boot should still be inspected. |
| Column pill outer-edge clipping (trip hypothesis) | Geometry places the outer border at about x442, while shadows/press swell extend beyond scrollable border-box overflow. Code supports the mechanism; desktop overflow does not reproduce native Safari's column paint boundary. | **Unverified on hardware; not claimed fixed.** Check ring and 1.12 press swell; inset keyline is an integration mitigation. |
| Smooth jump cancelled by sideways correction (trip hypothesis) | `follow()` issues instant `scrollTo({left:x, top:scrollY})` only if sideways position differs. This can interrupt smooth scrolling. The supplied video does not prove that drift occurred. | **Potential bug retained:** requires a reliable native drift reproduction before changing horizontal pinning, which prevents other real regressions. Documented stable-axis guidance. |
| Menu flicker / slow opening (trip hypothesis) | Trip CSS combined scroll-timeline transform with library translate, large blurred layers, `100lvh` overflow and root `:has()`. These custom CSS rules are not in Duet's shipped sidebar. Library groups also animate layout properties. | Integration mechanism supported by supplied code excerpts; **device performance unprofiled**. No claim that all jank is fixed. Profile Layers/Timelines and large-content performance. |
| Sidebar on wrong side / slide style | Supplied trip override right-anchored an absolute box against the page viewport, and forced width with `!important`; library default anchors left. Full-width reveal is intentional library behaviour, not proof of bad geometry. | Integration diagnosis supported; no trip code changed here. Guidance warns against internal geometry overrides. A drawer redesign is a separate UX decision. |
| Home page WebKit crash | Reproduced without JS or external assets. Home loads with videos removed; a minimal `<video src="/media/strip.mp4">` crashes this Linux WebKit media backend. | Layout contract moved to deterministic `/quality` in both engines. Chromium keeps a home smoke test; WebKit home media smoke explicitly skipped with reason. Physical Safari media playback pending; this is not claimed fixed in the product. |

## Hypothesis discipline

The supplied video cannot prove which menu control was tapped: selected row, burger and scrim can all close it. Re-selection suppression is independently reproduced; that does not establish the exact video touch. Source inspection supports mixed scroll-animation/large-blur jank mechanisms but is not a device profile. Crop evidence supports an overflow paint boundary but desktop screenshots cannot validate native chrome. No speculative timing patch or unconditional delayed scroll retry is shipped.

## Reference stack and decisions

[Radix's package](https://github.com/radix-ui/primitives/blob/main/package.json) uses Vitest, Testing Library, user-event, Playwright, axe and an SSR testing app. Duet adopts these test layers while retaining its useful pure geometry fixtures. [React Aria recommends semantic queries](https://react-aria.adobe.com/testing), which survive internal markup changes better than styling classes. [Storybook accessibility testing](https://storybook.js.org/docs/writing-tests/accessibility-testing) combines automated axe checks and manual assessment; Duet uses the existing site lab/fixture instead of adding a second demo system. [shadcn registry documentation](https://ui.shadcn.com/docs/registry) concerns code/registry distribution; Duet currently ships an npm package with exports, no registry or installer. Therefore the equivalent gate validates packed exports and installs that tarball into a fresh app, typechecks and builds it. If registry distribution is introduced, add schema/file/dependency validation and an actual CLI install/build test before publication.

The supplied Base UI/React Spectrum research also supports real-browser and visual coverage. These references inform the layers, not a claim of equivalent maturity. This initial suite and mandatory manual evidence are a foundation; real device access, broader screen-reader coverage and performance profiling remain necessary.

## Operating gates

See [CONTRIBUTING.md](../CONTRIBUTING.md), [the written matrix](DUO-TEST-MATRIX.md) and [integration guidance](QUALITY-INTEGRATION.md). CI runs every automated layer and preserves screenshots/videos/traces on failure. A real Duo Safari pass is required for interactive/layout changes; if unavailable, the PR stays draft with that check pending. Repository maintainers must configure branch protection to require the quality job; workflow YAML cannot enable protection by itself.
